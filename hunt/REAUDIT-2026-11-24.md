# Re-audit of the SSH CVE-hunt commits (2026-11-24)

Trigger: discovered that without `ASAN_OPTIONS=abort_on_error=1`, an ASan memory error ends a
fuzzing client with `exit(1)` instead of `SIGABRT`, so libafl records **no objective** and drops the
crashing input (looks like a benign "LLMP client exit / Good Bye"). `.cargo/config.toml` sets the
right options but cargo `[env]` only reaches `cargo run`/`cargo test`, never a binary launched
directly (every campaign + every replay). Signal crashes (SEGV) and claim objectives are unaffected.

Deciding factor per CVE = the ORACLE / crash type.

## CVE-2021-3634 — what changes

Lost organic hits in the broker stderr logs (`ERROR: AddressSanitizer: heap-buffer-overflow` in
`ssh_packet_set_newkeys`), none recorded as objectives:
- `t2_q2_cve20213634` (Q2): 6 reports, 0 objectives
- `q5focus` (first 80c): 16 reports, 1 objective (that one was noise)
- `_steplockq5f2` (80c step-locked): 70 reports, 1 objective (noise)
- `q5_iso_honest_rekey`: 3 reports, 0 objectives
- ~95 lost CVE crashes total, 0 recorded.

Corrected run `q5fix` (4×10c, honest-rekey-only, `abort_on_error=1`): a REAL CVE-2021-3634 objective
(replay = heap-buffer-overflow in `ssh_packet_set_newkeys`) after **53 s / ~262k execs**. The other 3
objectives replayed clean (load timeouts).

Control: a campaign on a seed that crashes → with default options **0 objectives** ("Good Bye"); with
`abort_on_error=1` → **578 objectives in 75 s**.

Invalidated conclusions (all on branch `cves/CVE-2021-3634`, pushed, no PR):
- `808baf3bb` Tier-2: "Q2 organic discovery NO — 0 finds in 15.7M execs" → **WRONG**; found ~53 s.
- `386f8838e` scaled campaign "0 finds in ~36M execs" → the campaign ran but detection was broken; the
  36M "0 finds" is an artifact of the lost crashes, not unreachability.
- `7705109af` improvement #2 "does NOT help, 0 crashes in 120k" → **WRONG**; the "0 crashes" was the
  same `Failure(1)` misclassification. #2 (group16-fallback seed) DOES reach the crash
  (ReplaceReuse E≈294 verified by replay with abort_on_error) — but it is MOOT: the plain honest seed
  already finds it in ~53 s once detection works.
- `495f6f76b` focused mutation harness: the harness/measurements are sound as term-level counts, but
  their "undiscoverable" framing is wrong.

Still valid for CVE-2021-3634:
- Tier-1 (`2ba7ffdb2`): witness fires on `-only-CVE-2021-3634`, patched on `-fix-all`,
  regression-clean. Uses `execute`/witness which surface the crash correctly. **stands.**
- Q4 honest→crash distance = 1 DY mutation (proven by probe execution). **stands.**
