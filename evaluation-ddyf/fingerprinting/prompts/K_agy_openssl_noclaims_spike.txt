## Why this should work (read these first)
- Claims for OpenSSL currently come from a hand-patched fork (github.com/tlspuffin/openssl,
  branches `fuzz-OpenSSL_3_x`) that injects `register_claimer`/`_inner_claimer` into OpenSSL
  source. Only 3.1.2/3.2.0/3.4.0 exist — that is why we cannot do contiguous versions.
- But claims are OPTIONAL and gated: `-DHAS_CLAIMS` is only set when a library's
  instrumentation metadata contains "claimer" (puffin-build/src/harness/mod.rs:75). In
  `tlspuffin/harness/openssl/src/put.c` every fork hook is under `#ifdef HAS_CLAIMS`; the
  basic PUT (SSL_new/SSL_do_handshake/SSL_read/SSL_write/SSL_get_error/SSL_state_string) is
  pure public OpenSSL API. The Rust glue even has an explicit no-claimer path
  (`tlspuffin/src/rust_put/claims.rs:1` -> `#[cfg(not(has_instr = "claimer"))]`).
- For FINGERPRINTING we use a WIRE-ONLY signature and we DO NOT want decryption to affect
  differences. No claims => no secrets => no decryption of the server's encrypted records.
  That is exactly the methodology we want. So a no-claims OpenSSL build from upstream tags
  should be sufficient.

## Step 2 — Make the signature work with NO decryption
Without claims, the server's encrypted records appear only as `OpaqueMessageFlight` (no parsed
`MessageFlight`). `_canon.normalize_knowledge` currently DROPS `OpaqueMessageFlight`
(_canon.py:60 returns None). Change it so the wire-only signature still captures what an
observer sees WITHOUT keys:
- For `OpaqueMessageFlight`, emit a normalized STRUCTURAL token instead of None: the record
  content-type(s) (handshake / application_data / alert / change_cipher_spec), the NUMBER of
  records, and a coarse length bucket — but NOT the ciphertext bytes (those are volatile;
  strip them like the other Payload rules). Inspect the actual `OpaqueMessageFlight` string
  shape first and design the token to match it.
- Keep everything else in `canonicalize_execution` as-is (server-role steps, error,
  executed_until). The result must be deterministic across repeated runs.
- Sanity: compute `get_signature` for the upstream openssl340u PUT on a couple of probe
  traces from candidates/manifest.csv; confirm you get a stable 64-hex signature (not ERROR).
